# Generative AI Chatbot

OpenAI API와 SQLite를 활용하여 구현한 터미널 기반 생성형 AI 챗봇입니다.

단순한 AI 대화 기능에서 시작하여 장기 기억, 대화 세션 관리, 대화 검색 및 요약 기능을 단계적으로 확장했습니다.

장기적으로 활용할 대화 정보와 세션별 대화 문맥을 분리하여 관리하며, 대화가 길어질 경우 오래된 메시지를 자동으로 요약하여 AI가 이전 대화의 주요 맥락을 계속 활용할 수 있도록 구현했습니다.

- **`database.py`**
  - SQLite 데이터베이스 초기화 및 데이터 접근 기능 관리
  
- **`config.py`**

## 핵심 설계

### 장기 기억과 대화 세션 분리

장기적으로 활용할 대화 정보와 대화의 문맥을 서로 다른 영역으로 분리하여 관리합니다.

장기 기억은 SQLite에 별도로 저장하여 새로운 대화 세션에서도 활용할 수 있도록 구성했으며, 일반 대화 기록은 `session_id`를 기준으로 각 세션의 문맥이 서로 섞이지 않도록 구현했습니다.

이를 통해 새로운 대화를 시작하더라도 필요한 장기 기억은 유지하면서, 이전 세션의 단기적인 대화 내용은 새로운 세션에 영향을 주지 않도록 구성했습니다.

### 세션 기반 대화 관리

각 대화를 독립적인 세션으로 관리하여 여러 대화의 기록과 문맥을 분리합니다.

현재 사용 중인 세션을 별도로 관리하며, 새로운 세션을 생성하거나 기존 세션으로 이동하여 저장된 대화 문맥을 다시 이어갈 수 있습니다.

또한 세션별 제목, 메시지, 요약 정보를 저장하여 대화가 많아진 이후에도 원하는 대화를 검색하고 관리할 수 있도록 구현했습니다.

### 대화 요약과 컨텍스트 요약 분리

대화 세션 전체를 사용자가 확인하기 위한 요약과 AI가 긴 대화의 문맥을 유지하기 위한 컨텍스트 요약을 별도로 관리합니다.

대화 요약은 세션의 전체 내용을 정리하여 사용자가 관리할 수 있도록 저장하고, 컨텍스트 요약은 오래된 메시지를 압축하여 이후 AI 대화의 입력 문맥으로 활용합니다.

두 요약의 목적을 분리하여 사용자에게 제공하는 대화 관리 기능과 AI 내부의 문맥 관리 기능을 독립적으로 처리할 수 있도록 구성했습니다.

### 긴 대화를 위한 컨텍스트 자동 요약

대화가 길어질수록 모든 과거 메시지를 매번 AI에 전달하지 않도록 오래된 메시지를 일정 단위로 자동 요약합니다.

최근 메시지는 원문 그대로 유지하고, 오래된 메시지는 컨텍스트 요약으로 압축하여 함께 전달합니다. 아직 요약 단위에 도달하지 않은 메시지는 원문 상태로 유지하여 대화 문맥에서 누락되지 않도록 구성했습니다.

마지막으로 요약한 메시지 ID를 체크포인트로 저장하여 이미 처리한 메시지가 다시 요약되는 것을 방지합니다.

### 메시지 수정과 요약 일관성 관리

저장된 메시지를 수정할 경우 기존 요약이 실제 대화 내용과 달라질 수 있으므로 요약 데이터의 일관성을 함께 관리합니다.

대화 내용이 변경되면 기존 대화 요약을 무효화하고, 이미 컨텍스트 요약에 포함된 메시지가 수정된 경우에는 해당 컨텍스트 요약과 체크포인트도 무효화하도록 구성했습니다.

이를 통해 수정된 대화 내용을 기준으로 필요한 요약을 다시 생성할 수 있도록 구성했습니다.

### 명령어 처리 모듈화

초기에 하나의 파일에 집중되어 있던 명령어 처리 기능을 역할에 따라 여러 모듈로 분리했습니다.

도움말, 설정, 삭제 확인, 장기 기억, 대화 관리 기능을 각각의 명령어 모듈에서 처리하고, `command_handler.py`는 사용자 입력을 적절한 모듈로 전달하는 라우터 역할만 담당하도록 구성했습니다.

이를 통해 새로운 명령어를 추가하거나 기존 기능을 수정할 때 관련 코드의 위치를 쉽게 파악할 수 있도록 구조를 개선했습니다.

| --------------------------------------------- | --------------------------------------------------------------- |
| `새대화`                                      | 새로운 대화 세션을 생성하고 해당 세션으로 이동합니다.           |

| `대화정보 <session_id>`                       | 특정 대화 세션의 정보를 확인합니다.                             |
| `대화보기 <session_id>`                       | 특정 세션에 저장된 대화 내용을 확인합니다.                      |

| `대화삭제 <session_id>`                       | 특정 대화 세션을 삭제합니다.                                    |

## 설치 및 실행

### 1. 저장소 복제

```bash
git clone https://github.com/ca1yp2/generative_ai_chatbot.git
cd generative_ai_chatbot
```

### 2. 가상환경 생성 및 활성화

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. 패키지 설치

```powershell
pip install -r requirements.txt
```

### 4. 환경 변수 설정

`.env.example` 파일을 복사하여 `.env` 파일을 생성합니다.

```powershell
Copy-Item .env.example .env
```

생성된 `.env` 파일에 OpenAI API 키와 사용할 모델명을 입력합니다.

```env
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=your_openai_model
```

`OPENAI_API_KEY`에는 발급받은 OpenAI API 키를 입력하고, `OPENAI_MODEL`에는 사용할 OpenAI 모델명을 입력합니다.

`.env` 파일에는 API 키가 포함되므로 Git에 업로드되지 않도록 `.gitignore`에 등록되어 있습니다.

### 5. 프로그램 실행

```powershell
python main.py
```

프로그램이 실행되면 터미널에 일반 대화를 입력하거나 지원되는 명령어를 사용할 수 있습니다.


## 환경 설정

프로그램의 기본 설정은 환경 변수와 `config.py`를 통해 관리하며, 실행 중 변경한 일부 설정은 `settings.json`에 저장됩니다.

`settings.json`에 저장된 설정은 프로그램을 다시 실행해도 유지됩니다.

현재 런타임에서 변경할 수 있는 설정은 다음과 같습니다.

- AI 대화에 사용할 최근 대화 기록 개수
- 장기 기억 디버그 출력 활성화 여부

`settings.json`은 사용자별 로컬 실행 설정이므로 Git에 포함되지 않도록 `.gitignore`에 등록되어 있습니다.


## 데이터베이스 구조

SQLite를 사용하여 장기 기억, 대화 세션, 메시지 및 현재 세션 상태를 관리합니다.

### `memories`

장기 기억의 key를 관리합니다.

하나의 key에 여러 값을 저장할 수 있도록 실제 값은 `memory_values` 테이블과 분리하여 관리합니다.

### `memory_values`

각 장기 기억 key에 연결된 값을 저장합니다.

`memories`와 외래 키로 연결되어 있으며, 하나의 key에 여러 값을 독립적으로 저장할 수 있습니다.

### `chat_sessions`

대화 세션의 정보를 관리합니다.

세션 제목과 대화 요약, AI의 문맥 관리에 사용하는 컨텍스트 요약 및 마지막으로 요약된 메시지의 위치를 함께 관리합니다.

### `messages`

사용자와 AI의 대화 메시지를 저장합니다.

각 메시지는 `session_id`를 통해 `chat_sessions`와 연결되며, 세션이 삭제되면 해당 세션의 메시지도 함께 삭제되도록 외래 키 관계를 구성했습니다.

### `chat_state`

현재 사용 중인 대화 세션을 관리합니다.

프로그램을 종료한 후 다시 실행해도 이전에 사용하던 세션을 이어갈 수 있도록 현재 세션 정보를 저장합니다.

### 주요 관계

```text
memories
    │
    └── memory_values

chat_sessions
    │
    └── messages

chat_state
    │
    └── 현재 chat_session 참조
```

장기 기억과 대화 기록은 서로 독립적으로 관리하여 대화 세션을 삭제하더라도 저장된 장기 기억은 유지할 수 있도록 구성했습니다.


## 주요 문제 해결

### 1. 대화 세션의 도입과 기존 메시지 구조 변경

#### 문제

초기에는 모든 대화 메시지가 하나의 기록으로 저장되어 있어 여러 대화를 독립적으로 관리하기 어려웠습니다.

대화 세션 기능을 추가하면서 기존 `messages` 테이블의 데이터는 유지하면서 각 메시지를 세션과 연결해야 했습니다.

#### 해결

`chat_sessions` 테이블을 추가하고 `messages`에 `session_id`를 연결하는 구조로 변경했습니다.

기존 데이터를 유지하면서 데이터베이스 구조를 단계적으로 변경하고, 외래 키 관계와 세션 연결 상태를 별도의 진단 스크립트로 확인했습니다.

이를 통해 기존 대화 기록을 유지하면서 여러 대화 세션을 독립적으로 관리할 수 있도록 구조를 확장했습니다.

### 2. 현재 대화 세션 상태 관리

#### 문제

여러 개의 대화 세션이 존재하게 되면서 단순히 가장 최근에 생성된 세션을 선택하는 것만으로는 사용자가 실제로 사용 중인 대화를 정확하게 판단할 수 없었습니다.

또한 프로그램을 다시 실행했을 때 이전에 사용하던 세션을 이어갈 방법이 필요했습니다.

#### 해결

`chat_state`를 통해 현재 사용 중인 세션 ID를 별도로 저장하도록 구성했습니다.

새로운 대화를 생성하거나 기존 대화로 이동할 때 현재 세션 상태를 갱신하고, 프로그램을 다시 실행했을 때도 저장된 세션 상태를 기준으로 대화를 이어갈 수 있도록 구현했습니다.

### 3. 긴 대화의 컨텍스트 관리

#### 문제

대화가 계속 길어질 경우 모든 과거 메시지를 매 요청마다 AI에 전달하는 방식은 비효율적이며, 대화 기록이 계속 증가하면서 컨텍스트 관리가 어려워지는 문제가 있었습니다.

#### 해결

최근 대화는 원문 그대로 유지하고 오래된 메시지는 일정 단위로 요약하며 `context_summary`에 저장하는 방식을 구현했습니다.

아직 요약 단위에 도달하지 않은 이전 메시지는 원문으로 유지하여 문맥에서 누락되지 않도록 했으며, `context_summary_message_id`를 체크포인트로 사용하여 이미 요약된 메시지가 중복 처리되지 않도록 구성했습니다.

이를 통해 전체 과거 메시지를 항상 그대로 전달하지 않으면서도 이전 대화의 주요 문맥을 AI가 계속 활용할 수 있도록 개선했습니다.

### 4. 메시지 수정에 따른 요약 데이터 불일치

#### 문제

이미 요약에 포함된 과거 메시지를 수정하면 저장된 요약과 실제 대화 내용이 서로 달라질 수 있었습니다.

특히 컨텍스트 요약이 이전 메시지 내용을 기반으로 생성된 상태에서 해당 메시지가 수정되면 잘못된 문맥이 이후 대화에 계속 사용될 가능성이 있었습니다.

#### 해결

메시지가 수정되면 기존 대화 요약을 무효화하도록 처리했습니다.

또한 수정된 메시지가 이미 컨텍스트 요약에 포함된 메시지인지 체크포인트를 기준으로 확인하고, 해당하는 경우 `context_summary`와 체크포인트도 함께 초기화하도록 구현했습니다.

이를 통해 변경된 메시지를 기준으로 필요한 요약을 다시 생성할 수 있도록 데이터 일관성을 유지했습니다.

### 5. 명령어 증가에 따른 코드 복잡도 개선

#### 문제

기능과 명령어가 증가하면서 하나의 명령어 처리 파일이 계속 커지고, 서로 다른 기능의 코드가 한곳에 모이기 시작했습니다.

이 구조에서는 새로운 명령어를 추가하거나 기존 기능을 수정할수록 코드의 위치와 역할을 파악하기 어려워질 수 있었습니다.

#### 해결

명령어를 역할에 따라 도움말, 설정, 삭제 확인, 장기 기억, 대화 관리 모듈로 분리했습니다.

`command_handler.py`는 직접 모든 명령어를 처리하지 않고 각 명령어 모듈로 입력을 전달하는 라우터 역할만 담당하도록 변경했습니다.

이를 통해 기능별 책임을 분리하고 향후 명령어를 추가하거나 수정하기 쉬운 구조로 개선했습니다.
